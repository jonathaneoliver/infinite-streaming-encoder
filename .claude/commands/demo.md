# demo

Drive the app with Playwright and turn the recording into a narrated, captioned
video. The tooling is `tools/demo/`; its README has the six steps. **This file
is the ORDER**, because the ordering is what goes wrong, and several steps are
expensive to redo — a 40-minute recording, a real cloud encode.

## Before anything: rehearse at smoke length

A 20s clip caught three wrong narration lines before the 5.6-minute cloud run,
for about a cent. Never take the long recording first.

```bash
cd tools/demo
SOURCE=smoke.mp4 OUTDIR=video-smoke TAG=smoke node record_local.js
```

Watch the webm it writes. You are checking the NARRATION against the ACTION,
not the video quality. Then, and only then, re-run with the real source.

## Preflight — check these four, every time

Each has produced a ruined take.

1. **Is anything non-terminal?** `curl -s localhost:8080/api/jobs`. A demo
   submitted alongside a real encode competes for the same worker pool, and the
   fan-out the demo is there to show gets starved.
2. **Are there terminal job cards on screen?** Clear them. Two `CANCELLED`
   cards sat visible through the entire fast-forward of the finished video.
3. **Does the output already exist?** `resolveCodec` skips a file whose
   `<stem>_<codec>` output is already in `OUTPUT_DIR`, so a second take produces
   a 0-stage job that "succeeds" in 35 seconds. Use **Re-encode**, not Encode —
   and set an output suffix (`TAG=`) so the demo never archives a real
   comparison encode.
4. **Is the farm dev-mounted from another worktree?** `/whats-running`. The
   demo records whatever that tree's Python does.

## The one ordering rule inside the drive

**Set the codec and ladder BEFORE any segment that narrates them.**

The codec checkboxes default to H.264 **and** HEVC. The first version narrated
"adding HEVC doubles the jobs" over a click that *removed* it, because the
codec was set after the segment that depended on it. If you add a segment that
describes a control, move the control's click above it.

Related, same class: `_detailsCollapsed()` returns `!_jobRunning(j)`, so a
running job's details are already open. A blind click on that toggle CLOSES the
chunk rows the demo exists to show.

## Then the tail

```bash
python3 narrator_app.py        # edit text, pick voices, set the FFWD range, export
python3 join.py local.mp4 cloud.mp4 encoder-demo-full.mp4
```

`join.py` refuses mismatched audio-track counts and mismatched video sizes
rather than producing a broken file — if it refuses, re-export the odd half
with the same voice selection, or re-record it at the same window size.

## The narrative is tracked; keep it that way

```bash
python3 edit_text.py save encoder-local     # cues.json -> narrative/, then commit
python3 edit_text.py load encoder-local     # narrative/ -> cues.json
```

After a take you were happy with, **save and commit the narrative**. That is
what makes the next edit reviewable and revertible. Prose edits belong in
`narrative/*.txt`, not in `cues.json` — the JSON is regenerated by every
recording.

`load` refuses if the narrative's line count differs from the recording's cue
count. That is not a nuisance to work around: lines are matched by index, so
applying anyway would shift the whole script onto the wrong moments and you
would not find out until playback. If the drive changed, re-`save` and re-apply
the edits.

## Cost

The local half is free. The cloud half launches real spot capacity and transfers
media — the reference run was $0.78. **Do not run the cloud recorder without
saying so and getting an answer**, the same rule as `make smoke-cloud`.

## Do not

- Do not `make deploy`, `farm-up` or `restart` to "get a clean state" mid-demo
  without checking for a running job first.
- Do not edit `scripts/infinite_streaming_encoder/` while recording — under
  `farm-dev-up` that lands in the next phase of the run being recorded.
- Do not touch `$SOURCE_DIR/smoke.mp4`. `make smoke-cloud` owns its mtime.
