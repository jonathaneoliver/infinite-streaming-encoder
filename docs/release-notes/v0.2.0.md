The first tagged release — a baseline for everything after it, and the point
from which generated changelogs have something to compare against.

A **parallel, chunking video encoder**: it splits a source into chunks and fans
the encode out across either **AWS Batch spot instances** or a **farm of your own
machines**. Same Python pipeline both ways; you pick the target per job. A thin
Go control plane plans the ladder, dispatches the chunks and streams live
progress to a single-page UI.

> Not a production encoding service or media origin. It is a hobbyist tool for
> generating test-ready ABR content and experimenting with ladders, packaging
> and spot-resumable fan-out.

## What it does

**Two targets, one pipeline.** Cloud runs as a Step Functions execution with
every chunk its own Batch job on spot capacity; local runs the same phases as
Temporal activities across a LAN farm. Step Functions decides what runs when,
Batch decides what machine it runs on — and Temporal plus the worker pool are
the local equivalents of that pair.

**Chunking that stays comparable.** Chunk boundaries land on a grid of
`lcm(segment, 6s)`, so the same clip cuts in the same places on every delivery
profile — four ladders that differ only in segment length no longer differ in
where the encoder resets. Chunk sizes are picked per variant from *measured*
encode speed, aiming at a target amount of work per chunk, so a cheap rung is
one long chunk and 4K HEVC is many short ones and they finish together.

**Ladders are configuration, not code.** A ladder is its rungs *and* its
delivery profile — segment, partial, GOP, VBV — because those are one decision,
and it is authored as data in `ladders.json`.

**Cost you can check.** The pre-flight estimate and the finished run's cost are
computed on the same basis: AWS bills the instance, not the vCPU-time jobs
allocate, so the estimate converts through a measured fleet-idle fraction rather
than quoting allocation and reporting rental. The allowance is shown, never
folded in, and no figure ever subtracts free tier.

**Built to survive interruption.** Encodes run in detached sibling containers
and reattach after a control-plane restart; spot reclaims are retried by Batch;
staging is reclaimed by three independent layers so a crashed job cannot leak
storage forever.

**A UI that describes itself.** Every control carries its own description in the
DOM, and both the accessibility layer and the demo recorder read *that* rather
than keeping a second copy that drifts.

## Getting started

```bash
make doctor      # preflight: .env, host tools, per-target config
make farm-up     # cluster + server + a local worker
make smoke       # a real short encode, end to end
```

`make status`, `make fleet-check` and `make cloud-payload` answer the four
different questions hiding inside "is it deployed?".

## Known limitations

- **No hardware encoding.** VideoToolbox was dropped in the rewrite — it only
  works on macOS hosts, not Linux workers.
- **One cloud compute environment** (Graviton), so the CPU-architecture control
  is inert and cost projection hardcodes graviton on purpose.
- **`make smoke-cloud` and `make deploy` cost money and mutate shared
  infrastructure.** Both are deliberate, manual, maintainer-run steps.

## Demo

`encoder-demo-full.mp4` — an 18m 48s narrated walkthrough attached to this
release.

**Local half (12m 37s)** — a full encode on the farm: picking a source, the
controls describing themselves, the cost estimate, the chunk grid filling in as
the fan-out proceeds, the machine timeline, and the finished output.

**Cloud half (6m 11s)** — the same clip on AWS: a Step Functions execution with
every chunk a Batch job on spot capacity, the fleet coming up, what it actually
cost against what the same ladder costs elsewhere, and the per-machine chunk
timeline.

Both halves fast-forward the encoding itself ×30; everything else is real time.
1680×1080, captions burnt in, two narration tracks (track 1 Jonathan, track 2
Alice). The narration is the application's own control descriptions, read out of
the DOM at record time.
